👋 Meet the Docs Assistant

Describe what you want fixed, updated, or created in Windows developer documentation — in plain English. The assistant asks a couple of smart follow-up questions, creates the tracking item, and kicks off an agent to draft the change. You review the pull request before anything publishes.

1
Describe it

Tell the bot in a Teams chat what's wrong or missing — no forms, no ADO fields to fill in yourself.

2
Answer a question or two

Only when needed: go-live timing, source spec, or scope — skipped entirely for simple fixes.

3
Confirm the summary

Review a structured card before anything is created — your one checkpoint to catch misunderstandings.

4
Review the PR

An agent drafts the change against the right repo. You approve before it merges and publishes.

What actually gets written to ADO

No custom fields or work item types — everything maps onto System.Title, System.AreaPath, tags, and a machine-parseable comment block in System.Description, per the existing work-item-schema.md ledger convention already used by the scheduled sweeper. This keeps chat-filed requests and automatically-detected findings in one consistent queue the sweeper can read.
